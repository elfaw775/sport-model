# 马球节（fetlock）病变检测 —— 拆分与训练指南

> 目标：用本地 YOLO 训练一个「检测马球节病变（骨折）」的模型。
> 唯一目标类别：**病变（class 0）**。`annotation mark`（部位标记）已按要求忽略。

---

## 0. 一句话总结

- 数据已拆好：`datasets/sporthorse/`（train 48 / val 10 / test 10 + `data.yaml`）。
- 用 1 条命令就能开始训练（见第 4 节）。
- **68 张全是骨折病例、没有任何「正常马」负样本**，模型会「见谁都报病变」。做「有无病变」的二分类/筛查前，必须补正常片。详见第 6 节。

---

## 1. 数据现状（重要，先读）

| 项 | 数量 |
|---|---|
| 图片总数（`骨折x线片（总）/`） | 68 |
| 病变（class 0）框总数 | 81（56 张 1 个、11 张 2 个、1 张 3 个） |
| 有病变框的图片（正样本） | **68 / 68（100%）** |
| 无病变框的图片（负样本/正常马） | **0** |
| 被忽略的 `annotation mark` 框 | 29（已剔除，不参与训练） |

来源链路：CVAT → 导出 **COCO 1.0** → `coco2yolo.py` 转 YOLO → `split_dataset.py` 拆分。

**已确认的标注语义**：
- `病变`（COCO category 1）→ 训练类别 `0`，唯一目标。
- `annotation mark`（COCO category 2）→ 部位标记，**训练时忽略**。
- 病变类型全部是「骨折」（来自标注属性 `病变类型=骨折`）。
- 每张图 = 一匹不同的马 → 按【图片】拆分，不存在同马跨集合泄漏。

**⚠️ 三个必须知道的数据问题：**

1. **没有负样本（最严重）**：68 张全是有骨折的片子。YOLO 只能学到「病变长什么样」，学不到「正常片长什么样」。所以对一张正常 X 光片，模型很可能还是硬报一个框。要真正回答「这匹马有没有病变」，**必须补一批确认无病变的正常 X 光片**（建议至少 30~50 张，和正样本 1:1 左右）。
2. **样本量偏小**：68 张正样本做检测训练偏少，容易过拟合；指标会虚高。建议后续补到 200+ 张。
3. **11 个框越界（已自动裁剪）**：COCO 导出里 11 个 `rotation≈251~277°` 的旋转框外接框溢出了图片边界，转换时已裁剪到边界内，不影响训练。对应图片：`16-侧位、17-正位、18-正位、19-正位、20-侧位、45-正位、47-正位、50-正位、52-正位、6-正位、67-正位 p1骨折`。方便的话去 CVAT 核对一下这几张的框画得对不对。

### 当前拆分结果（seed=42，比例 7:1.5:1.5）

| train | 48 | 57 |
| val | 10 | 12 |

## 4. 训练

### 4.1 确认 `data.yaml`

已生成在 `datasets/sporthorse/data.yaml`：

```yaml
path: /Users/huhaodong.11/stu_train/datasets/sporthorse
train: images/train
val: images/val
test: images/test
names:
  0: lesion
```

> 类别名用 ASCII `lesion`（不是中文）。原因：中文类别名会让 ultralytics 去下载 22MB 的
> `Arial.Unicode.ttf`，而且会尝试写到工作区外的 `~/Library/Application Support/Ultralytics/`，
> 在 DSH 的 workspace-write 沙箱下会直接报 `PermissionError` 退出。ASCII 名会命中系统自带的
> `Arial.ttf`，不需要任何下载。类别名只用于显示，不影响训练效果。

### 4.2 训练命令

先设置两个环境变量（把 ultralytics 的配置/字体目录、matplotlib 缓存都放进工作区，
避免沙箱权限问题），再训练：

```bash
cd /Users/huhaodong.11/stu_train
source .venv/bin/activate

export YOLO_CONFIG_DIR="$PWD/.ultralytics"
export MPLCONFIGDIR="$PWD/.mplconfig"

yolo detect train \
    model=yolo11n.pt \
    data=datasets/sporthorse/data.yaml \
    epochs=200 \
    imgsz=640 \
    batch=16 \
    device=mps \
    seed=42 \
    patience=50 \
    project="$PWD/runs/horse" \
    name=lesion_v1
```

> `project` 用绝对路径，否则 ultralytics 会把它再套一层，变成 `runs/detect/runs/horse/...`。
>
> 之后所有 `yolo ...` 命令（`val` / `predict`）也都建议先 `export` 上面这两个变量；也可以写进
> `~/.zshrc` 一次性配好，避免每次都要设。

| 参数 | 含义 | 建议 |
|---|---|---|
| `model=yolo11n.pt` | 预训练权重（nano，最小最快） | 小数据先用 n；想更准用 `yolo11s.pt` |
| `epochs=200` | 轮数 | 小数据给大轮数，靠 `patience` 早停 |
| `imgsz=640` | 输入尺寸 | 图片 141~1837px 不等；640 会把小图放大，可接受，也可试 512 |
| `batch=16` | 批大小 | MPS 报 OOM 就降到 8 |
| `device=mps` | Apple GPU | 报错改 `device=cpu` |
| `patience=50` | 早停 | 防过拟合烧时间 |

> 数据增强默认已开（Mosaic、翻转、缩放、色彩抖动），小数据有用，不用额外配。

### 4.4 本次实验对比（2026-11-03）

同一个数据拆分（train 48 / val 10 / test 10，seed=42），只改「预训练模型 + 是否冻结骨干」：

| 实验 | 最佳 epoch | val mAP50 | test mAP50 | test P | test R |
|---|---|---|---|---|---|
| ① yolo11n 全量微调（基线） | 49 | 0.162 | 0.0077 | 0.0015 | 0.333 |
| ② yolo11n + `freeze=10` | 71 | 0.199 | 0.0214 | 0.092 | 0.083 |
| ③ **yolo11s + `freeze=10`** | 93 | **0.211** | **0.089** | 0.138 | 0.25 |

**结论：**

- 本来就是在用 COCO 预训练的 `yolo11n` 微调；换成**更大的预训练模型 `yolo11s` + 冻结骨干**，
  test mAP50 从 0.0077 提升到 0.089（约 **11 倍**），是当前最佳组合。
- **冻结骨干（`freeze=10`）是小数据防过拟合的关键**，precision 提升最明显。
- 但绝对值依然低（mAP50 0.089），**数据量才是天花板**。

**推荐训练命令（当前最佳）：**

```bash
yolo detect train \
    model=yolo11s.pt \
    data=datasets/sporthorse/data.yaml \
    epochs=200 imgsz=640 batch=16 device=mps seed=42 patience=50 \
    freeze=10 \
    project="$PWD/runs/horse" name=lesion_yolo11s_freeze10
```

权重：`runs/horse/lesion_yolo11s_freeze10/weights/best.pt`（19.2MB）

**说明与注意：**

- `freeze=10`：冻结前 10 层（backbone 前段），只训检测头和后段，小数据下比全量微调稳。
- 数据只有 68 张、val/test 各 10 张，指标方差很大；**别用 test 反复挑模型**，这里的对比仅作参考。
- [HuggingFace 上的 yolo11-fracture](https://huggingface.co/Jesteban247/yolo11-fracture-onnx) 只有 ONNX、
  且是人类骨折数据，**不能用来做训练初始化**，只能参考它「freeze=10」的配方。

**改进方向（按收益排序）：**

1. **补数据到 200+ 张**（最大杠杆）。
2. **补正常（无病变）图**，让 precision / recall 有意义。
3. 现有 68 张可再试：`--ratio 0.85 0.075 0.075`（train 57 张）、`imgsz=768`、`freeze=5` 或 `freeze=15`。
4. 换更大模型收益递减，先解决数据。

    model=runs/horse/lesion_v1/weights/best.pt \

## 6. 关键风险与建议（务必看）

1. **没有负样本 = 无法真正回答「有没有病变」**。现在这 68 张全是骨折片，模型能学会「病变在哪」，但不会判「正常」。要用于筛查/二分类，必须补正常 X 光片（建议 ≥30~50 张，且按马拆分）。这是当前**最大的缺口**。

2. **正样本 68 张偏少**，过拟合明显。建议补到 200+ 张、并保持正负平衡。

3. **指标不可全信**：68 张拆到 test 只有 10 张，方差大。补数据后建议用多个随机种子拆分看均值，或做交叉验证。

4. **11 个越界框已裁剪**：如果这 11 张在 CVAT 里看框位置明显不对（旋转框），建议重画成普通矩形，再重新走第 2 节流程。

5. **关于「检测框」还是「分类」**：你现在产出的是检测框（能给出病变位置）。如果只要「有/无病变」，可先用检测框的置信度/数量做规则判断；数据够了再考虑单独训分类模型。

6. **路径含中文/空格**：`骨折x线片（总）` 和部分文件名带中文与空格，脚本已按精确同名处理；训练时 `data.yaml` 用绝对路径最稳。
